# DNS Management

Daedalus manages authoritative zone contents as part of DNS server host-side
state.

## Hosts

Recursive and authoritative DNS host membership lives in inventory. Use
`svc_dns_recursive` and `svc_dns_authoritative` group membership when current
host state is needed. Address, listener, and resolver values belong in
host/group vars, not in docs.

## Managed State

Daedalus manages:

- Unbound package, config, service, listen addresses, access-control, and
  internal stub-zone or forward-zone metadata
- NSD package, config, service, listen addresses, zone registration metadata,
  and generated zone files for managed zones
- basic validation commands such as `unbound-checkconf`, `nsd-checkconf`,
  `nsd-checkzone`, and local `dig` checks

Recursive DNS stubs `alflag.internal` to the authoritative DNS hosts.

Authoritative DNS records live in inventory vars, not in docs.

## Managed Zones

The default inventory manages:

- internal parent zone
- server identity zone
- access endpoint zone
- management reverse zone
- DMZ reverse zone

The `srv.alflag.internal` namespace is for server identity records. The
`access.internal` namespace is for access endpoint records. Do not aggregate
host or service records into `alflag.internal`.

Compatibility aliases are not part of the default managed data, and managed
zones should not use CNAME records without an explicit reason in the inventory
review. Reverse zones return server identity names from `srv.alflag.internal`.

`minecraft.internal`, `service.internal`, CLIENT reverse, and TRANSIT reverse
zones are not managed initially.

Do not edit generated zone files manually. Zone files are generated by Daedalus
and must not be edited on DNS hosts. Record changes must update the structured
zone data and the explicit zone serial in inventory.

Zone data uses this shape:

```yaml
dns_authoritative_zones:
  - name: <zone-name>
    file: <absolute-zone-file-path>
    managed: true
    serial: <zone-serial>
    soa:
      mname: <primary-name-server>
      rname: <responsible-mailbox>
      refresh: <seconds>
      retry: <seconds>
      expire: <seconds>
      minimum: <seconds>
    ns:
      - <name-server>
    records:
      - name: <record-name>
        type: <record-type>
        value: <record-value>
```

## Add Or Change Records

Add metadata under `ansible/inventories/default/group_vars/svc_dns_authoritative.yml`.
Use real record values in inventory, not copied examples in docs. Update the
zone serial whenever records change.

Use `infra check`, `infra diff`, and `infra apply` as the normal operation path
for converging DNS desired state.

## Validation

From the control node:

```bash
infra check --limit svc_dns_recursive
infra diff --limit svc_dns_recursive
infra check --limit svc_dns_authoritative
infra diff --limit svc_dns_authoritative
```

On a recursive DNS host:

```bash
unbound-checkconf
dig +short <query-name> <query-type> @<recursive-listener>
```

On an authoritative DNS host:

```bash
nsd-checkconf /etc/nsd/nsd.conf
nsd-checkzone <zone-name> <absolute-zone-file-path>
```
